# تشغيل المشروع محلياً عبر Docker

هذه أول مرة يُشغَّل فيها كود `maktaba-core` و`maktaba-theme` فعلياً على
مفسّر PHP وقاعدة بيانات حقيقيين — كل ما جرى قبل ذلك كان تدقيقاً نصياً
ثابتاً للكود (Static Analysis) فقط. هذا الملف لا يُستخدم في الإنتاج.

## المتطلبات

- Docker Desktop مُثبَّت ويعمل (Windows / macOS / Linux)

## التشغيل

من داخل مجلد `repository/` (المجلد الذي يحتوي `docker-compose.yml`):

```bash
docker compose up -d
```

انتظر حتى تكتمل تهيئة قاعدة البيانات (أول تشغيل فقط، قد يستغرق دقيقة).

## الخطوات بعد التشغيل

1. افتح `http://localhost:8080` وأكمل معالج تثبيت WordPress القياسي
   (اسم الموقع، مستخدم مدير، كلمة مرور).
2. من لوحة التحكم: **الإضافات ← أضف جديد ← WooCommerce ← تثبيت وتفعيل**
   (إلزامي أولاً — `maktaba-core` يعتمد عليه بالكامل).
3. **الإضافات ← فعّل "Maktaba Core"** — هذا يُنشئ الجداول الثلاثة
   (`mkt_inventory_movements`, `mkt_purchase_items`, `mkt_customers`)
   تلقائياً عبر `dbDelta()`، بلا حاجة لتنفيذ ملفات `db/migrations/*.sql`
   يدوياً — هي موجودة كمرجع توثيقي فقط.
4. **المظهر ← أضف جديد ← ابحث "Storefront" ← ثبّت** (ثيم مجاني رسمي —
   `maktaba-theme` هو Child Theme فوقه، ولن يعمل بلا تثبيته أولاً).
   بعدها: **المظهر ← فعّل "Maktaba Theme"**.
5. جرّب الوظائف الأساسية كما ورد في القائمة السابقة (منتج تجريبي،
   عملية شراء، تغيير حالة طلب، إلخ).

## فحص قاعدة البيانات مباشرة (اختياري)

افتح `http://localhost:8081` (phpMyAdmin) — سجّل الدخول بنفس بيانات
`MYSQL_USER` / `MYSQL_PASSWORD` من `.env` أو القيم الافتراضية في
`docker-compose.yml`. تحقق من وجود الجداول الثلاثة أعلاه ببادئة `wp_`.

## استيراد حزمة ناشر كاملة (بيانات + صور أغلفة) دفعة واحدة

راجع `docs/publisher-pack-guide.md` للمواصفة الكاملة. باختصار: ضع
ملف الحزمة (`.zip`) داخل `docker/wp-cli-scripts/packs/`، ثم:

```bash
docker compose run --rm wpcli sh /scripts/import-publisher-pack.sh /scripts/packs/اسم-الحزمة.zip
```

هذا ينشئ كل الكتب دفعة واحدة **مع صور أغلفتها الفعلية**، ويحسب
أسعارها بالعملتين تلقائياً، ويمنع تكرار أي كتاب له ISBN مطابق لكتاب
مستورَد مسبقاً.

## إضافة منتج عبر سطر الأوامر (WP-CLI)

بدل الإدخال اليدوي من لوحة التحكم، يمكن إنشاء منتج/كتاب كامل البيانات
عبر WP-CLI. أضفنا خدمة `wpcli` بالضبط لهذا الغرض (لا تعمل تلقائياً —
تُستدعى عند الحاجة فقط):

```bash
docker compose run --rm wpcli sh /scripts/add-ibn-khaldoun.sh
```

هذا يُنشئ منتج "مقدمة ابن خلدون (3 أجزاء) - دار نهضة مصر" ببياناته
الحقيقية (مؤلف، ناشر، سنة طبعة، عدد صفحات) مأخوذة من بحث فعلي على
الإنترنت — راجع التعليقات أعلى ملف السكربت
`docker/wp-cli-scripts/add-ibn-khaldoun.sh` لمعرفة أي القيم افتراضية
(كالسعر) يجب تعديلها لتطابق مكتبتك فعلياً، وأيها مُتحقَّق منها.

لإنشاء منتج آخر بنفس الطريقة: انسخ الملف وعدّل القيم — الحقول
`_mkt_isbn` / `_mkt_language` / `_mkt_page_count` / `_mkt_publication_year`
/ `_mkt_condition` هي بالضبط ما يقرأه `BookDetailsMetaBox` في لوحة
التحكم، فستظهر معبَّأة تلقائياً عند فتح المنتج للتعديل هناك.

## متابعة الأخطاء لحظياً

```bash
docker compose logs -f wordpress
```

أو من داخل الحاوية:

```bash
docker compose exec wordpress tail -f wp-content/debug.log
```

أي خطأ يظهر هنا، الصقه لي كاملاً وسأصلحه.

## تعديل الكود أثناء التطوير

مجلدا `wp-content/plugins/maktaba-core` و`wp-content/themes/maktaba-theme`
مربوطان مباشرة (Bind Mount) بنفس ملفات هذا المستودع — أي تعديل يُحفظ هنا
ينعكس فوراً في المتصفح بلا إعادة بناء أو إعادة تشغيل الحاوية (تحديث
الصفحة فقط كافٍ).

## البداية من الصفر

```bash
docker compose down -v
docker compose up -d
```

`-v` يحذف بيانات قاعدة البيانات وملفات WordPress الأساسية أيضاً —
استخدمه فقط إذا أردت تثبيتاً نظيفاً كاملاً.

## لماذا لا يوجد Dockerfile مخصَّص؟

الصور الجاهزة الرسمية (`wordpress:php8.2-apache` و`mysql:8.0`) تكفي
تماماً هنا — لا حاجة لأي خطوة بناء (build) مخصصة أو إضافات PHP إضافية.
هذا التزام بمبدأ Zero-Cost/Zero-Complexity المعتمد في بقية المشروع.
إذا احتجت لاحقاً تثبيت WP-CLI داخل الحاوية أو امتدادات PHP إضافية،
أخبرني وسأضيف Dockerfile مخصصاً عندها فقط.
